# 運用・保守ガイド

このアプリを長く使い続けるために、開発者として意識しておくべきことをまとめています。

## 1. 構成の考え方

```
src/
  data/          教材データ（ここを編集するのが日常の「運用」）
    week1-4.ts   週ごとの単語・フレーズ
    data.test.ts 教材データの自動チェック
  hooks/         ブラウザ機能（読み上げ・音声認識・録音・進捗保存）のラッパー
  components/    画面
  storage.ts     localStorage の読み書き
```

- **データと画面を分離**しているので、単語の追加・修正は `src/data/` だけ触れば済みます。
- バックエンド（サーバー・DB）を持たない**静的サイト**です。サーバー代・セキュリティパッチ・障害対応がほぼ不要で、個人運用に向いています。
- その代わり「覚えた」の記録はブラウザ内（localStorage）にしか残りません。PCとスマホで共有したくなったら、そのときにバックエンド（Supabase / Firebase など）を検討します。

## 2. 教材データを編集するときのルール

| ルール | 理由 |
| --- | --- |
| `id` は変更・再利用しない | 進捗の保存キー。変えるとその単語の「覚えた」が消える。削除した ID を別の単語に使うと、別の単語が「覚えた」扱いになる |
| 繁体字で書く | 台湾は繁体字。IME を「中国語（繁体字・台湾）」に。テストが代表的な簡体字の混入を検出します |
| 拼音は台湾の読みに合わせる | 例：星期 xīngqí、品質 pǐnzhí、危險 wéixiǎn。迷ったら教育部の辞書で確認 |
| 編集後は `npm test` | ID 重複・空欄・声調記号漏れを検出。CI でも自動実行され、失敗するとデプロイされません |

## 3. 公開範囲と情報管理（重要）

- GitHub Pages は**インターネットに公開**されます。リポジトリが public ならソースコードも誰でも見られます。
- **取引先の社名・案件名・金額・図面番号などの業務情報は教材データに入れない**でください。単語は一般的な用語にとどめ、固有の情報は社内の管理された場所で扱いましょう。
- 社外公開を避けたい場合は、private リポジトリ＋有料プランの Pages、または社内のホスティング環境を使います。会社の情報セキュリティ規程も確認してください。
- 🎤 発音チェック（音声認識）は、ブラウザ経由で音声が外部サービス（Chrome なら Google）に送られます。一般的な教材フレーズの読み上げに限って使う分には問題になりにくいですが、業務上の機密を話さないよう注意。⏺ 録音機能は端末内だけで完結します。

## 4. ブラウザ依存の機能について

音声まわりは Web 標準 API（Web Speech API / MediaRecorder）を使っていて、**環境によって動作が変わります**。

| 機能 | Chrome / Edge | Safari | Firefox |
| --- | --- | --- | --- |
| 読み上げ | ○ | ○ | ○（OSの音声次第） |
| 発音チェック | ○ | △（バージョン次第） | × |
| 録音 | ○ | ○ | ○ |

- 読み上げの声は **OS にインストールされた音声**に依存します。台湾の音声（zh-TW）がない場合は OS の言語設定で「中国語（台湾）」を追加してください。
  - Windows：設定 → 時刻と言語 → 言語 → 中国語（繁体字、台湾）を追加し音声をダウンロード
  - Mac / iPhone：設定 → アクセシビリティ → 読み上げコンテンツ → 声 → 中国語（台湾）
- マイク機能は **HTTPS か localhost でしか動きません**。GitHub Pages は HTTPS なので問題ありませんが、社内サーバー等に置く場合は注意。
- 音声認識の結果は「数字」（例：兩點 → 2點）や同音異字で一致率が下がることがあります。判定は目安として使い、⏺ 録音で耳で比べるのが確実です。
- 新しいブラウザ機能を使うときは、`recognitionSupported` のように**対応していない環境でも画面が壊れない**よう、機能検出してから使うのが鉄則です。

## 5. 依存関係のアップデート

- 実際にインストールされるバージョンは `package-lock.json` で固定されます。CI は `npm ci` でロックファイル通りに入れるので、手元と同じ環境で検証されます。
- **関連パッケージはセットで上げる**：Vite のメジャー更新では `@vitejs/plugin-react`・`vitest`・`@types/node` の対応バージョンも上げる必要があります（例：Vite 8 には plugin-react 6 以上、Node.js 22.12 以上）。`npm install` で `ERESOLVE` エラーが出たら、この組み合わせ違いを疑ってください。`--force` で無理に入れると壊れたまま動くので避ける。
- `.github/dependabot.yml` により、月1回アップデートの PR が自動で作られます。
  - CI（テスト＋ビルド）が通ればマージしてOK。
  - React・Vite のメジャーバージョン（例：18 → 19）は破壊的変更があるので、リリースノートを読んでから。
- 依存パッケージは最小限（React と Vite のみ）にしてあります。**パッケージを増やすほど保守コストとセキュリティリスクが増える**ので、追加は慎重に。

## 6. localStorage のデータ形式を変えるとき

保存キーには `studyTaiwan.progress.v1` のようにバージョンを付けています。保存形式を変える場合は：

1. 新しいキー（`v2`）を作る
2. 起動時に `v1` があれば読み込んで `v2` 形式に変換する移行処理を書く
3. しばらくしてから `v1` の読み込み処理を削除する

これをしないと、利用者の学習記録が消えます。

## 7. トラブルシューティング

| 症状 | 確認すること |
| --- | --- |
| 公開ページが真っ白 | `vite.config.ts` の `base` がリポジトリ名と一致しているか（`/studyTaiwan/`） |
| 音が出ない | 設定タブで音声が選ばれているか、端末がマナーモードでないか、OSに中国語音声があるか |
| 発音チェックボタンがない | ブラウザが非対応（Chrome / Edge を使う） |
| マイクが使えない | ブラウザのサイト設定でマイクが許可されているか、HTTPS で開いているか |
| デプロイされない | GitHub の Actions タブでエラーを確認。テスト失敗だと公開されない |
